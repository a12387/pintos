>B3: Describe your code for reading and writing user data from the kernel.

对于存放在用户栈中的参数，直接通过`pagedir_get_page()`获取物理地址，并读取到内核中的变量里。对于字符串等，传入的指针按前述方式获得，而实际数据并不会读入内核中，而是采用将对应用户地址转换成物理地址后，由内核直接读写的方式。

>B5: Briefly describe your implementation of the "wait" system call
>and how it interacts with process termination.

在wait调用者的`children`列表中，找到pid符合的进程的`child_info`结构体，设置其中的`waited`为true并对其中的信号量`wait_sema`进行sema down操作。

wait与进程退出的交互主要由该`child_info`结构体承担，这一结构体在进程创建时使用malloc分配，进程退出时不会释放，而是当父进程退出时由父进程释放。进程退出时，设置结构体中`exit_status`变量，表示退出状态（若未经exit就退出，可能是被中止等情况，这时`exit_status`为默认值-1，表示出错）；设置`exited`为true，提示父进程应当释放这一块内存；sema up信号量`wait_sema`，防止后续可能的wait。而wait中只要成功sema down，就表明等待的进程已退出，可以获得退出状态并释放资源。

>allocated resources (locks, buffers, etc.) are freed?  In a few

读写用户数据时产生的错误，直接由读写函数统一处理，系统调用函数需要直接处理的只有传入数据的合法性。对于传入的整数内容，不需要过多检查；对于文件描述符，只需要在文件表中查询即可得知合法性；对于字符串指针，在转为物理地址前需要先确认整个字符串都是有效的用户地址；对于缓冲区指针，则要确认整个缓冲区都在用户内存范围内。对于这些工作，当发现错误时，会直接返回或调用`thread_exit()`中止，所以错误处理并不繁杂。

#### SYNCHRONIZATION

>B7: The "exec" system call returns -1 if loading the new executable
>fails, so it cannot return before the new executable has completed
>loading.  How does your code ensure this?  How is the load
>success/failure status passed back to the thread that calls "exec"?

在`process_start()`中分配了一个临时的信号量，并初始化为0，通过参数传递给新创建的线程。新线程在函数`start_process()`中，直到load完成之前，都不会up这个信号量，由此保证创建者一定在完成加载后返回。

此外，返回值变量的地址也作为参数传入新线程中，加载成功/失败状态通过这一地址传递，若加载失败则设置为-1，创建者会执行与线程创建失败相同的操作。

>B8: Consider parent process P with child process C.  How do you
>ensure proper synchronization and avoid race conditions when P
>calls wait(C) before C exits?  After C exits?  How do you ensure
>that all resources are freed in each case?  How about when P
>terminates without waiting, before C exits?  After C exits?  Are
>there any special cases?

- P在C退出前调用wait：
    - `wait_sema`信号量没有up，P会在此等待，直到C退出。
    - C的其他资源在退出时释放，`child_info`在P调用wait时释放
- P在C退出后调用wait：
    - `wait_sema`在C退出时up，因此P不会等待，而是立刻返回。
    - C的其他资源在退出时释放，`child_info`在P调用wait时，在`wait_sema`down之后释放
- P在C退出前终止：
    - 由于没有wait，因此没有sema down，不会死锁。
    - P退出时将C的parent设置为NULL，C退出时会自行释放分配的所有资源。
- P在C退出后终止：
    - C在退出时，`wait_sema`会up，而P退出时，会对所有子进程的`wait_sema`try down，若成功说明该子进程已退出，可以释放资源，否则仅设置子进程parent为NULL
